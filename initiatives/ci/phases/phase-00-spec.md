# Phase 00 — Steel thread: the rewritten `ci.yml` green on its own PR

**Goal (one line):** `.github/workflows/ci.yml` is rewritten in place into the one-Linux PR gate (ubuntu, Node 24, jobs `changes` · `quality` · `bats (0..3)` · `node-test` · `test` · `security` · `face` · `ci-tier`), goes green per job on its own PR, and merges after the owner's §5 protection cut-over. Cost and wall clock are measured against the baseline.
**Appetite:** 0.5 day, with TWO CI rounds budgeted. Round 2 is the attack fix plus any Node-24 break. Needing a third round triggers the kill-criteria conversation. Blown appetite = cut scope or kill, never extend silently.
**Depends on:** none
**REQs closed here:** REQ-01 (REQ-03 merged into it, 2026-10-24)

**Decisions applied:** ADR-2201 (gate shape), ADR-2203 (Node 24), ADR-2204 (named required checks).

**Why only `ci.yml`:** face-coverage inventories workflows by file name (`face-coverage.mjs:352`), so rewriting `ci.yml` in place keeps `workflow:ci` and needs no face change. `weekly.yml`/`release.yml` and the deletions move face's `expected-set.json` and land in Phase 01.

**What the old file really does (read 2026-10-24):** the `selftest` job's own steps are only `Version gate` (`bash .claude/scripts/review/arc-scan/version-gate.sh`), `Product manifests lint` (`node .claude/scripts/core/product-lint.mjs`), `Run bats self-tests` (with a declared-vs-executed TAP reconcile) and the `911` floor. **Every other arc gate (gate-parity, brain-drift, wiki, face-coverage, portfolio-board, kickoff-lint…) runs as a bats suite** (ADR-2016). So in Phase 00 they keep running inside the `bats` shards, and `quality` carries only the two non-bats gates.

**Local runs this phase (CI-A, owner 2026-10-23, supersedes "never run a suite on this box"):** the session MAY run the new scripts below, the two `quality` commands, the kickoff-lint, wiki and face-coverage generators, and single named bats files. It never runs the full bats suite locally (about 4.3 h on Windows).

4. **Logic out of YAML** (fixed-defects d). New scripts, each a CLI with a realpath-both-sides main guard:
   - `.claude/scripts/core/ci-changes.mjs --base {sha} --head {sha}` or `--files {path}`. It prints `face=true|false` and `citier=true|false` lines, which the job appends to `$GITHUB_OUTPUT`. `face` = any path under `face/`. `citier` = any path under `docker/`, `.claude/scripts/review/arc-tools-image.sh` or `.claude/scripts/review/arc-scan/adapters/trivy*`. **Fail open:** if `--base` is missing (dispatch) or empty, the diff exits non-zero, or the list is empty, it prints both `true`. Phase 00 has no docs-only skip: bats and node-test always run, and the `code` output arrives with REQ-02 in Phase 01.
   - `.claude/scripts/core/ci-bats-shard.sh {i} {n}`: the file list is `find tests -name '*.bats' | LC_ALL=C sort | awk -v i="$1" -v n="$2" 'NR % n == i'`. An empty list → exit 1. It runs `bats --print-output-on-failure` over the list, teed to `${RUNNER_TEMP:-${TMPDIR:-/tmp}}/bats-shard-{i}.tap`, then runs the old `_declared`/`_reconcile` functions moved verbatim from `ci.old.yml:216-232`. Declared for the shard = `_declared` over exactly that shard's file list; executed = the `^(ok|not ok) ` lines of that TAP log. Executed must equal declared, and a `# bats warning:` line is a failure.
   - `.claude/scripts/core/ci-floor.mjs [--baseline N]`: declared = the `^[[:blank:]]*@test[[:blank:]]` count summed over every `tests/**/*.bats` (verified 2026-10-24: **4815** over 243 files, the same regex as `_declared`), plus the sum of every `tests/*/.count` file. **`.count` format:** one non-negative decimal integer and a newline, nothing else; any other content → exit 2 `bad .count: {path}`. Floor = `BASELINE` (constant `4815`, overridable by `--baseline`) minus the number of **drop rows**. **Drop-row grammar**, the same in `tests/DROPPED.md` and every `tests/*/MIGRATED.md`: a markdown table row whose second cell is exactly `DROPPED`, i.e. `| {old @test name} | DROPPED | {reason} |`; a row with an empty reason → exit 2. If the real tree's count ever differs from 4815 at build time, STOP: BASELINE changes only with the owner told, never to make a test pass. Declared below floor → print `test count {d} < floor {f}` and exit 1. Above → print `test count {d} > floor {f}: raise BASELINE to {d}` and exit 0. **No shared count file exists**, so parallel lane PRs never conflict on a number (attack B1). The per-shard reconcile proves bats executed what was declared, so the floor counts declared tests safely.
   - `.claude/scripts/core/ci-install-tools.sh`: the Linux branch of the old `Install gitleaks` (VER 8.30.1) and `Install opengrep` (v1.26.0, `opengrep_manylinux_x86`) steps, moved verbatim, plus `npm install -g bats` and `sudo apt-get install -y jq`. Each tool is best-effort as before, and it ends with the old `Tool banner`.
   - Each new synced file gets its `products/core/manifest.json` `scripts`/`files` line in the same commit (product-lint stops every job otherwise).
5. **`ci.yml` rewrite** (same file name, `name: arc-ci` unchanged, all old comments that describe the matrix deleted):

   - Every job: `runs-on: ubuntu-latest`, `timeout-minutes` (changes 5, quality 15, bats 30, node-test 15, test 5, security 15, face 15, ci-tier 30), and `if: ${{ github.event_name == 'workflow_dispatch' || github.event.pull_request.draft != true }}`, ANDed with the job's own condition.
   - `uses:` only `actions/checkout` and `actions/setup-node`, each pinned to the commit of its newest `v4.x.y` tag. Resolve it with `git ls-remote --tags https://github.com/actions/{name} 'v4.*'` and take the peeled `^{}` SHA when the tag is annotated, followed by `# v4.x.y`. `setup-node` uses `node-version: '24'`.
   - `changes`: checkout with `fetch-depth: 0`, then `node .claude/scripts/core/ci-changes.mjs --base ${{ github.event.pull_request.base.sha }} --head ${{ github.sha }} >> "$GITHUB_OUTPUT"`.
   - `quality` (`needs: changes`): `bash .claude/scripts/review/arc-scan/version-gate.sh` and `node .claude/scripts/core/product-lint.mjs`.
   - `bats` (`needs: changes`), `strategy: { fail-fast: false, matrix: { shard: [0,1,2,3] } }`, job name `bats (${{ matrix.shard }})`: `bash .claude/scripts/core/ci-install-tools.sh`, then `bash .claude/scripts/core/ci-bats-shard.sh ${{ matrix.shard }} 4`.
   - `node-test` (`needs: changes`): `find tests -name '*.test.mjs' | wc -l` printed. If zero AND no `tests/*/.count` exists, it prints `node:test: 0 files, 0 lanes migrated` and passes. Otherwise it runs `node --test "tests/**/*.test.mjs"` (quoted glob; a directory argument is not a test list on Node 22+), and a reported `# tests 0` fails.
   - `test`: `needs: [changes, quality, bats, node-test]`, `if: ${{ !cancelled() && (github.event_name == 'workflow_dispatch' || github.event.pull_request.draft != true) }}`. ## Rabbit holes in this phase

- A red bats shard on Node 24 (A-01): run the failing files alone first (`bash .claude/scripts/core/ci-bats-shard.sh` over just them, on a dispatch with Node 22 and with Node 24). Passes alone on both → ambient shard-order state: file it and fix the test. Fails only on 24 → a Node-24 break: fix it in code. Never skip it.
- Re-weighting shards with timing files: round-robin only; balance only has to be rough at 1x billing.
- Touching protection or visibility from the session: print the list and STOP.

## Out of scope for this phase

- `weekly.yml`, `release.yml`, `dependabot.yml`, deleting the throwaways, ESLint, the pre-push hook, root `npm audit`, the docs-only skip, rules rewrites (all Phase 01).

## Non-negotiables (verbatim from PLAN)

- Branch-only writes: every change goes on a `feat/ci-*` or `migrate/{lane}` branch through a PR; never a commit to `main`.
- Never edit branch protection: at the cut-over, STOP and print the §5 step-2 list for the owner.
- Every action in every workflow is pinned by full commit SHA, with the tag in a trailing comment.
- Path filtering happens at job level through a `changes` job, never through workflow-level `paths` / `paths-ignore`.
- `migrate-guard` and the per-lane floors are FAIL from birth; ESLint starts WARN (CI-S).
- launch's ci provider and face's expected-set change only through `/arc-change` on their own lanes (CI-P, Phase 01).
- `npm run ci` locally before every push, then read CI per job with `ci-digest.mjs`, head SHA asserted.
- A migrated test asserts the SAME behaviour: no loosened assertion and no skipped, pending or `.only` test; a dropped test is listed with its reason in `MIGRATED.md`.
- Runtime `dependencies` stays `{}`; ESLint is the only devDependency, with a committed lockfile.
- Two-surface adversarial pass via `/arc-attack` (ADR-0226) per PR, carrying `initiatives/ci/fixed-defects.md`; the author is never the attacker.

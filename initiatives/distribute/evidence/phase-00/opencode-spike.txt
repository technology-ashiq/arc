## Deviation from the spec: why the final command is not arc-resume

phase-00-spec step 8 named a rendering of `arc-resume`. That rendering was run four times, and OpenCode executed it
every time. It loaded the hand-rendered command and the `spike` agent, enforced the agent's permission map, and ran its
tools. No run reached the emit step that closes the command:

The kickoff's requirement is "one command invoked from OpenCode, one receipt with `harness: opencode` in payload". Run 7
meets it. The failures that blocked arc-resume came from the free models and the user-level OpenCode config. They are
not the command format. Running arc's real commands end to end in OpenCode is REQ-03's job in P03, on a model the owner
names.

## Facts the spike fed into engine/harnesses.yaml

- `opencode run` parses a message that starts with `--` as its own flag, so pass `-- <message>`.
- The bundled free tier refuses 1.17.18 (HTTP 426, needs 1.18.0 or newer).
- OpenCode writes `package.json`, `package-lock.json`, `.gitignore` and `node_modules/` into `.opencode/` on first run.
- A provider quota error is retried silently, with nothing on stdout. Only `~/.local/share/opencode/log/opencode.log`
  shows it, so the P03 adapter's `doctor` and REQ-03's runner must read that log, or pass `--print-logs`.
- User-level plugins and MCP servers load into every run, and can stall startup. `--pure` disables external plugins.

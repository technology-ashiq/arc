# Phase 04 — owner action: the three `.claude/settings.json` edits, applied

**Applied by the owner 2026-08-09.** Landed in `feat/policy-owner-settings` (PR #147), off `main`.

Phase 04's 26 findings closed as 23 code fixes, 2 measured rejections and **1 owner action**. The
owner action was not a workflow choice. `.claude/settings.json` is on ADR-0502's un-grantable
resource list *and* inside the harness's own `permissions.deny`, so the agent that found these
three holes is refused `Edit` and `Write` on the one file that closes them, by two independent
layers. The finding could be written; it could not be applied. That is the rule working.

`docs/owner-action-settings-json.md` carried the reasoning. `docs/owner-paste-STEP1-settings.json`
and `docs/owner-paste-STEP2-settings.json` carried the exact bytes — whole-file replacements
generated *from the live file*, because a diff-shaped instruction is a task, and a task handed to
the owner is the agent's job left undone.

## What changed

| # | Finding | Before | After |
|---|---|---|---|
| 1 | The deny floor did not cover the guard's own files | 24 entries, none for `.claude/hooks/**` or `.claude/scripts/hq/lib/policy/**` | **37 entries**, 10 of them naming a guard file |
| 2 | The write matcher missed two tools that write to disk | `Edit\|Write` | `Edit\|Write\|MultiEdit\|NotebookEdit` |
| 3 | The MCP surface reached no policy check at all | 2 `PreToolUse` matchers; `policy-hook.mjs`'s per-server capability table was unreachable | **3 matchers** — `mcp__.*\|Agent\|Task\|WebFetch\|WebSearch` routes to it |

Finding 1 was ordered first for a reason worth keeping written down: with the hook disarmed — the
shipped default — one session could permanently disarm every future armed one, because nothing
restored what it removed. Every later edit is only as durable as that one.

## What proves it on CI, not here

Two tests read this file rather than a fixture of it, which is the only reason they can notice an
un-applied edit:

- `tests/policy-hook.bats` **LAYER 2** — reads `permissions.deny` and asserts the static floor
- `tests/policy-hook.bats` **PHASE 04** — reads the `PreToolUse` matchers

`tests/fixtures/sync-golden/tree-manifest.txt` line 223 was regenerated in the same commit.
`.claude/settings.json` is hash-pinned by the byte-identity gate, so this file changing without the
manifest changing is three red CI legs. Regenerated by running the real `sync-to-project.sh` into a
scratch tree and re-hashing — exactly one line differs, which is itself the check that nothing else
moved.

## Why this landed on its own branch

absorb's PR (#138) was open and mid-cycle when the owner applied these. Putting policy's owner
action in absorb's PR would land a second lane's change under absorb's review. Fresh branch off
`main`, two files, one lane.

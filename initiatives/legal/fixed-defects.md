# legal lane -- fixed defects, as the attacker carries them

> Generated from `initiatives/legal/evidence/fixed-defect-list.md` (the table, which stays the
> record) into the bullet shape `build-attack-input.mjs` reads. Until 2026-10-06 the attacker
> looked here, found nothing, and ran with NO carried list. A new hole goes into BOTH files in
> the commit that fixes it.
- **literal-control-byte** (row 1, `.claude/scripts/legal/lib/yaml.mjs`, Phase 00): The NUL-byte guard and the BOM strip were each written with the LITERAL character in the source. `grep` then read the whole file as binary and reported `Binary file ... matches`, so any later pattern-based patch would have matched nothing. This is `arc-absorb` 2026-08-09 reproduced exactly — including the irony, since the file doing it is the guard against control characters.
- **regex-that-cannot-match** (row 2, `.claude/scripts/legal/lib/schema.mjs`, Phase 00): The two-or-more-spaces check was written `/{2,}/` — a quantifier with nothing before it. That is NOT a syntax error: Annex B reads a bare `{2,}` as the literal text `{2,}`, so the regex compiled, matched nothing, and the FREE-TEXT run-of-spaces rule would have reported clean forever. Same family as `arc-memory` 2026-08-12 (a gate that printed its contract and compared against nothing) — the check existed, ran, and could not fail. Fixed to `/[ ]{2,}/`, where the quantifier's target is impossible to misread.
- **false-positive-on-correct-input** (row 3, `.claude/scripts/legal/lib/lints.mjs`, Phase 00): trace-lint's branch-mismatch check fired for every NON-selected branch that listed a clause, so a clause legitimately shared by two branches reported a mismatch against a venture it described perfectly. It fired on the very first render of a correct page. The question is not "is this clause listed under some branch that was not chosen" but "is it listed under the branch that WAS". A check that is noisy on correct input teaches its reader to skip it.
- **conditionally-required-unconditionally-emitted** (row 4, `products/legal/templates/v1/{terms,privacy}.tmpl.md`, Phase 00): `PRIVACY.PROCESSOR`, `PRIVACY.SUBPROCESSORS` and `TERMS.PROCESSOR_ROLE` were REQUIRED only when `stores_third_party_client_data=true` but emitted with no `when=` guard at all, so three fixtures rendered a processor clause for a venture that holds nobody else's records. Completeness-lint cannot see this class — it only checks presence. trace-lint caught all three, unplanted, which is the closest thing to a real negative control this phase produced.
- **two-keying-schemes-in-one-lookup** (row 5, `products/legal/data/vocab.json`, Phase 00): The label tables were keyed by VOCABULARY name (`operator_type`) while the template asks for `label.<field path>` (`operator.type`). The lookup returned undefined and the render died. Two keying schemes in one file is how a lookup silently returns nothing; the file now says which one it uses and why.
- **vacuous-by-construction** (row 6, `tests/legal-probe.mjs`, Phase 00): The NFC-versus-NFD canonicaliser case was written as two typed literals. Typed literally, an editor or a filesystem normalises both to one form and the case compares a string with itself — passing whatever the canonicaliser does, inside the test written to prove normalisation happens. Rebuilt from `\u` escapes with a guard that refuses to run if the two inputs are equal.
- **negative-control-that-cannot-fail** (row 7, mutation controls (`prove-mutants`), Phase 00): TWO of eight mutants came back green and neither was a lint hole. `branch-leak` was rendered against the gateway fixture, where an unguarded gateway clause is correct — a leak is only observable from a branch that was NOT chosen. `denylist-bypass` was rendered against a clean page, where an emptied denylist has nothing to miss; it proves something only PAIRED with a claim (red with the list, green without). Both controls were fixed rather than the green being explained away.
- **fixtures-that-cannot-distinguish** (row 8, `tests/fixtures/legal/ventures/**`, Phase 00): All six fixture ventures shared one domain and one operator name, so if the renderer had rendered venture A's facts under venture B's name, every email and URL on the page would still have looked correct. Found by READING a rendered page, not by any lint. Each fixture now carries its own domain, operator and refund window.
- **promise-stripped-from-identical-data** (row 9, `products/legal/templates/v1/privacy.tmpl.md` + fixtures, Phase 01): **All three text-attack panels made this their number one finding, independently.** A venture whose `data_categories` include `client-matter-content` but whose `stores_third_party_client_data` is false rendered a page that ITEMISED other people's records and then carried no processor clause, no confidentiality commitment, no no-training promise and no sub-processor list — collecting exactly what the protected venture collects, with every protection deleted and nothing on the page saying so. Closed as a cross-field schema rule (those categories now force the flag) plus a fixture rebuild.
- **branch-guard-on-the-wrong-field** (row 10, `products/legal/templates/v1/{refund-cancellation,pricing}.tmpl.md`, Phase 01): The merchant-of-record render said Razorpay issues the receipt and then printed the operator's own GSTIN on "every invoice we issue" — because the GST clause was gated on `gst_registered` alone. The regulator panel's worst finding: the consumer could not tell who they paid, who invoices them, or whose address to serve. Closed by `derived.invoice_kind`, which has THREE states because two could not express it.
- **guard-coupled-to-an-unrelated-fact** (row 11, `products/legal/templates/v1/privacy.tmpl.md`, Phase 01): "Who else touches the data" was gated on whether the CUSTOMER stores client records, so a venture with a host and an email provider disclosed neither. Whether the customer holds third-party records has no bearing on whether the operator uses AWS. Two panels found it independently. Now gated on `derived.subprocessors`.
- **clause-alive-in-a-posture-that-cannot-have-it** (row 12, `products/legal/templates/v1/refund-cancellation.tmpl.md`, Phase 01): The auto-renewal clause rendered for a venture whose own terms say it takes no gateway payments and invoices by hand — describing a mechanism the same page says does not exist. Now gated on `derived.autorenew`.
- **a-promise-with-no-clock** (row 13, every page, Phase 01): Each panel found the same shape separately: "as soon as we know", "before we charge you", "on the schedule set out below" (pointing at a schedule that did not exist), "we start the refund within 2 working days of agreeing it" with no deadline to agree. Closed by making every numbered promise a `commitments.*` fact the venture chooses, so a page can never print a promise nobody made.
- **helper-under-bats-run** (row 14, `tests/legal-lints.bats`, Phase 01): The mutation helper was invoked as `run _mutate_and_render ...`. bats `run` executes in a SUBSHELL, so `SANDBOX` and `MUTANT_STATUS` were set in a process that immediately exited and every assertion afterwards read an empty variable. Nine tests failed for a reason with nothing to do with the lints they were testing.
- **assertion-that-passes-on-two-error-strings** (row 38, `tests/legal-publish-gate.bats`, `tests/legal-pins.bats`, Phase 02): The five-shape gate test asserted only `!= 0`, so three shapes passing at 3 ("parser refused the file") read the same as 2 ("a target is there") — including the idiomatic shape the original bypass used. And the two-set test compared two shas without checking either probe SUCCEEDED: `run` folds stderr into `$output`, and two failures differ *because the paths differ*, so the inequality held and the test passed having compared two error messages.
- **guard-inspects-the-object-not-the-output** (row 37, `.claude/scripts/legal/lib/checklist.mjs`, Phase 02): The blank-row guard checked `built.outcome` on the object while the row was rendered into a markdown table. A note containing ` | ` rewrote the columns to its right — the rendered outcome said NOT-APPLICABLE while the object said PASS — and a newline split the row so the second physical line rendered with no outcome at all. Notes with delimiters are now refused, and `renderChecklist` asserts its own RENDERED line and cell counts.
- **deliverable-with-zero-tests** (row 36, `.claude/scripts/legal/lib/checklist.mjs`, Phase 02): The whole launch checklist — four outcomes, the ADR-1201 row counts, the NOT-APPLICABLE branch, the blank-row guard — had no test of any kind. Every body could have been deleted and the suite stayed green. `tests/legal-checklist.bats` now covers each.
- **normalises-inputs-not-outputs** (row 35, `.claude/scripts/legal/lib/canonical.mjs`, Phase 02): `bytesHash` hashed raw text while the engine normalised every input it read. arc's own repo hides this behind `.gitattributes`; the venture repo the generated guard ships into has none, so on a Windows checkout every `.mdx` arrives as CRLF and EVERY page verified as TAMPERED on an untouched tree. A guard that cries wolf on a clean checkout is one people switch off.
- **unvalidated-input-into-generated-shell** (row 34, `.claude/scripts/legal/lib/checklist.mjs`, Phase 02): `ci-guard` interpolated `--venture` and `--dir` into a double-quoted line of the bash it writes into somebody else's repo. Both attackers got command execution (`$(...)`, backticks), and one turned `--dir` into a guard that exits 0 having verified nothing. CLAUDE.md's rule verbatim, in a generator, in the one verb that never called the confinement function whose comment reads "every path through it".
- **trusts-the-declared-version** (row 33, `.claude/scripts/legal/lib/receipts.mjs`, Phase 02): `canRederive` compared the preimage label against the current one, so ANY unrecognised label excused a hash mismatch. A tamperer who could edit the record could relabel it to `arc-legal-canon/99`, get UNVERIFIABLE instead of TAMPERED, and read back "re-publish under the current format" — an instruction to launder the edit. The docstring said classification never trusts the declared version; the code did.
- **evidence-claims-more-than-it-proves** (row 40, `.claude/scripts/legal/lib/checklist.mjs`, Phase 02 (2026-10-06)): A PASS carrying a served excerpt and page hash proves only that a human pasted text from the approved page; nothing fetched the URL. The row now says `self-attested, not fetched` rather than letting the excerpt imply a probe ran.
- **transient-error-read-as-refusal** (row 39, `.claude/scripts/legal/arc-legal.mjs`, Phase 01 (2026-10-06)): `writeAll` returned false on any throw, so EAGAIN from a full non-blocking pipe refused a healthy propose. EAGAIN is retried, bounded; only EPIPE and the rest refuse.
- **escape-covers-only-c0** (row 38, `.claude/scripts/legal/arc-legal.mjs`, Phase 01 (2026-10-06)): `JSON.stringify` escapes only code points below 0x20, so a ledger name with a C1 control, a bidi override or U+2028 reached the reviewer's terminal raw. Every non-printable-ASCII code point is escaped. Check every other place a recorded string is printed to a human.
- **diff-not-bound-to-what-it-diffed** (row 37, `.claude/scripts/legal/arc-legal.mjs`, Phase 01 (2026-10-06)): Propose showed a diff against the ledger as it stood; publish recomputed against the ledger as it stands later, with nothing binding the two. The approval now carries `previous_published_sha256` and publish refuses PREVIOUS_MOVED.
- **fingerprint-is-an-oracle** (row 36, `.claude/scripts/legal/lib/receipts.mjs`, Phase 01 (2026-10-06)): `factsFieldPrints` committed one sha256 per facts field to arc's PUBLIC ledger, including fields no page prints. A digest of a low-entropy private value (a yes/no flag, a name) lets anyone confirm a guess. Only template-interpolated fields get their own print now; every other field folds into one print no weaker than the `facts_sha256` already there. Any digest of a single value written to a public file has this class.
- **one-line-stands-in-for-another** (row 35, `.claude/scripts/legal/arc-legal.mjs`, Phase 01 (2026-10-06)): With no field prints on the old record, a re-publish whose clauses also moved printed the clause lines and NO facts line and no WARN, because the opaque test was "facts moved AND no clause moved". A clause change is not evidence the facts change was shown.
- **walk-drops-what-it-cannot-enumerate** (row 34, `.claude/scripts/legal/lib/receipts.mjs`, Phase 01 (2026-10-06)): The facts walk recursed into anything `typeof object`, so a Date, a Map or an empty mapping had no own keys and vanished from the prints entirely: a change to it could never be named. Only plain non-empty mappings are descended into; everything else is a leaf.
- **prototype-key-on-a-plain-object** (row 33, `.claude/scripts/legal/lib/receipts.mjs`, Phase 01 (2026-10-06)): `out["__proto__"] = x` on `{}` is silently dropped, and `field in before` matched inherited `constructor`. Null-prototype maps and `Object.hasOwn`.
- **path-from-the-record-not-confined** (row 32, `.claude/scripts/legal/lib/receipts.mjs`, Phase 02): `verifyPublished` joined a page id read out of the published record straight into a path, so a record naming `../decoy/terms` had verify hash an untouched copy OUTSIDE the publish directory and report INTACT on the defaced one inside it.
- **listing-not-recursive** (row 31, `.claude/scripts/legal/arc-legal.mjs`, Phase 02): `readdirSync(dir)` is flat, so an unapproved page one directory down (`out/en/terms.mdx`) published at exit 0 while the identical bytes at `out/terms-v2.mdx` were refused. A static host serves `/en/terms` exactly as it serves `/terms-v2`.

- **twin-fix-at-twelve-lines** (row 29, `.claude/scripts/legal/lib/receipts.mjs`, Phase 02): The unapproved-file check was added to `verifyChain` and NOT to `verifyPublished`, twelve lines below it in the same file — and verify is the half the generated guard runs continuously in the VENTURE's repo, the one place no twin-fix sweep of this repo can reach. - **case-sensitive-suffix-on-a-case-insensitive-fs** (row 28, `.claude/scripts/legal/lib/receipts.mjs`, Phase 01): `PAGE_UNAPPROVED_FILE` tested `entry.endsWith(".mdx")`. - **test-asserts-the-wrong-law** (row 26, `tests/legal-publish-gate.bats`, Phase 01): "The engine still ships no publish verb at all" stopped being true the moment `publish` was built, and the test passed for the wrong reason anyway — it invoked publish with `--out` instead of `--dir`, so the exit 2 it saw was an argument error.

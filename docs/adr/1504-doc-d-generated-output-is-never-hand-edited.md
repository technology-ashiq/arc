# ADR 1504 — DOC-D: generated output is never hand-edited; CI regenerates and fails on a dirty diff

**Status:** accepted
**Date:** 2026-09-25
**Product:** docs
**Reversibility:** two-way
**Revisit trigger:** the regenerate-and-diff check flaps on a tree nobody changed (A-05) → the nondeterminism is fixed at its source (sort, strip time, normalise EOL); the check is never relaxed or skipped.

## Context

Locked (DOC-D). ADR-0201 applied this rule to the three generated commands. `docs/wiki/**` is a
second generated surface.

This session cannot write under `.github/` (memory: `github-dir-write-denied-route-gates-through-bats`),
so a new workflow step is not available. The existing CI already runs every `tests/*.bats` file on
three OS legs.

## Options considered

1. **A new CI workflow step** — not writable from here.
2. **A bats suite that regenerates into a scratch dir and diffs against the committed tree** — runs on all three legs through the existing sharded bats job.

## Decision

Option 2. Every generated file starts with a banner:
`<!-- GENERATED by .claude/scripts/docs/wiki-build.mjs — DO NOT EDIT. Narrative lives in docs/wiki/_narrative/. -->`.
`tests/docs-render.bats` runs `wiki-build --out <scratch>` and fails, naming the first differing
path, if the scratch tree and the committed `docs/wiki/` differ by one byte, one missing file or
one extra file. Output is deterministic by construction: every list sorted by a byte-order
comparator (never locale), no timestamps, no absolute paths, LF endings, `.gitattributes` pinning
`docs/wiki/** text eol=lf`.

## Consequences

A hand edit to a generated page turns CI red on the next PR. The mutant control for this check is a
scratch tree with one byte changed in one page, asserted RED.
